# IkeOru — Product Brief

> Learn. Do. Prove.

## Problem

Professionals often know automation could reduce repetitive work but do not know how to turn a workplace task into a safe trigger, input, AI step, condition, action, output, and human-review point. Existing tools assume that fluency; theory-only learning does not show whether someone can apply it responsibly.

## Product

IkeOru is an academy-first, practical AI-powered learning and workforce-capability platform—not simply a workflow execution tool. It teaches the concepts and business context behind a workplace process before asking learners to apply them. Guided practical work then connects theory to an honest workflow result, and meaningful assessment checks what the learner understands and can do.

The product's learning model is **Learn → Do → Prove**:

- **Learn:** build foundations through objectives, definitions, context, worked examples, common mistakes, and knowledge checks.
- **Do:** practise a bounded, synthetic scenario with support, then move toward more independent application where the path allows it.
- **Prove:** demonstrate theoretical understanding and practical application against explicit objectives through a server-graded assessment.

The Moonshot MVP has two guided Academy-and-Lab paths:

- **Sales → Qualify a New Lead** teaches AI-assisted interpretation and server-controlled internal follow-up policy.
- **HR → Candidate Screening** teaches evidence-based comparison against explicit job-related criteria, missing-information handling, and mandatory human review.

The current local implementation provides ordered objective-led sections, worked examples, common-mistake explanations, server-checked knowledge checks, constrained Labs, and one server-graded independent scenario for both paths. The independent scenario requires evidence-based choices and is part of practical assessment readiness; it remains introductory evidence, not a broad competence claim.

Portfolio, badges, progress tracking, and organization reporting support this learning evidence. They do not substitute for teaching, practice, or assessment: a lesson completion is not mastery, an assessment pass is not broad workplace certification, and an achievement is awarded only when backend prerequisites are met.

## Value proposition

IkeOru turns “I have heard of automation” into observable introductory capability:

- **Learn:** understand the role of AI and deterministic controls in a workplace workflow.
- **Do:** make bounded choices, connect concepts to behaviour, and run a synthetic, server-controlled exercise.
- **Prove:** complete a server-graded theory-and-practice assessment and, when backend prerequisites are met, add an achievement and project evidence to a private-by-default portfolio.

## Specific target user

An entry-level sales development representative at a small business-to-business software team who manually reviews inbound leads, decides which need prompt attention, and has little prior automation experience. This is a target-user archetype, not a named customer, interview, or measured outcome claim.

Candidate Screening is a second learning path in the same workforce-capability product. It uses synthetic examples only, does not infer or use protected characteristics, does not invent qualifications, and never makes a hiring decision or autonomous employment recommendation.

## Scope and honesty

Only Sales lead qualification and HR candidate screening are active. Marketing, Finance, Operations, Customer Support, Business Intelligence, and all other named Sales/HR paths are Coming Soon. The MVP has no real CRM, email, ATS, or hiring integration.

OpenAI live mode is optional and server-configured. The deterministic mock adapter supports local development and automated tests but is visibly labelled and is never presented as a successful live AI call. No customer, interview, deployment, live-provider, time-saving, or learning-outcome claim is implied without separate evidence.
